典型工作流程

新功能开发流程：
  1. /grill-with-docs - 深入访谈并创建文档
  2. /to-spec - 将对话转化为规格说明
  3. /to-tickets - 将规格分解为问题
  4. /implement - 实现功能
  5. /code-review - 代码审查
测试驱动开发 (TDD) 流程：
  1. 红灯：编写一个失败的测试
  2. 绿灯：编写代码使测试通过
  3. 重构：优化代码结构

核心概念详解

问题追踪器 (Issue Tracker)：
  • 管理项目问题的工具
  • 支持 GitHub Issues、Linear 或本地文件
  • 用于存储和管理问题，跟踪工作进度
问题 (Issues)：
  • 被追踪的工作单元
  • 可以是 Bug、Task、Spec 或 Slice
  • 是 Skills 工作流的核心
分类角色 (Triage Roles)：
  • 问题的状态标签
  • 常见角色：needs-triage、ready-for-afk、in-progress、done
  • 用于管理工作流程
共享语言 (Shared Language)：
  • 项目术语表
  • 帮助 AI 理解项目上下文
  • 减少沟通成本，提高代码质量

学习建议

初学者路径：
  1. 先阅读 整体架构图，了解全貌
  2. 学习 安装步骤图，完成安装
  3. 查看 核心概念图，理解关键概念
  4. 尝试 工作流程图 中的简单流程
注意事项：
  • 不要一次性安装所有技能，从核心技能开始
  • 每个技能都有详细的文档，遇到问题先查看文档
  • 实践是最好的学习方式，多尝试不同的技能组合
